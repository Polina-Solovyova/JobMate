# 🚀 JobMate — персональный Telegram-ассистент для поиска вакансий

[![Python Version](https://img.shields.io/badge/python-3.11%2B-blue)](https://www.python.org/)

[![License: AGPL v3](https://img.shields.io/badge/License-AGPL_v3-blue)](https://www.gnu.org/licenses/agpl-3.0)

[![Telegram Bot API](https://img.shields.io/badge/Telegram%20Bot%20API-brightgreen)](https://core.telegram.org/bots/api)

[![Telethon](https://img.shields.io/badge/Telethon-1.x-blueviolet)](https://docs.telethon.dev/)

**JobMate** — Telegram-ассистент для автоматического поиска вакансий в Telegram-каналах.

Пользователь подключает свой Telegram-аккаунт, добавляет доступные ему каналы, создаёт собственные фильтры, а JobMate отслеживает новые публикации и отправляет уведомления о вакансиях, соответствующих активным фильтрам.

Каждый пользователь работает со своей Telegram-сессией, каналами, фильтрами и историей обработанных постов. Данные разных пользователей изолированы друг от друга.

## 🌟 Возможности

### 👥 Многопользовательский режим

JobMate рассчитан на работу с несколькими пользователями.

Для каждого пользователя отдельно хранятся:

* Telegram-сессия;
* список отслеживаемых каналов;
* фильтры вакансий;
* обработанные посты;
* состояние мониторинга каналов.

Пользовательские данные связаны с `user_id`, поэтому один пользователь не получает данные и уведомления другого пользователя.

---

### 🔐 Подключение личного Telegram-аккаунта

Пользователь подключает свой Telegram-аккаунт через команду:

```text
/connect
```

JobMate запускает процесс авторизации Telegram-аккаунта с использованием Telethon.

После успешной авторизации создаётся и сохраняется отдельная Telethon-сессия пользователя.

При последующих запусках приложения JobMate проверяет существующие сессии и автоматически запускает мониторинг для авторизованных пользователей.

> Файлы Telethon-сессий содержат авторизованный доступ к Telegram-аккаунту и должны храниться в защищённом месте.

---

### 📢 Мониторинг Telegram-каналов

Пользователь может добавлять Telegram-каналы, доступные его подключённому аккаунту.

В разделе «Мои каналы» доступны:

* добавление канала;
* просмотр добавленных каналов;
* включение и отключение мониторинга;
* удаление канала;
* повторная проверка доступа к каналу;
* возврат в главное меню.

После добавления канала JobMate сохраняет его в MongoDB и начинает отслеживать новые публикации.

Мониторинг выполняется отдельным Telethon-клиентом для каждого пользователя.

---

### 🎯 Персональные фильтры вакансий

Пользователь может создавать фильтры на естественном языке.

Например:

```text
продуктовый дизайнер, стажер
```

или:

```text
UX/UI дизайнер удалённо без опыта
```

Фильтр может содержать несколько условий.

В интерфейсе доступны:

* создание фильтра;
* просмотр фильтров;
* редактирование;
* включение;
* отключение;
* удаление.

Активные фильтры используются при обработке новых публикаций.

---

### 🧠 Определение вакансий и сопоставление

Для каждой новой публикации JobMate сначала определяет, является ли она вакансией.

После этого публикация проверяется относительно активных пользовательских фильтров.

Результат сопоставления содержит:

* `filter_id`;
* название фильтра;
* факт совпадения;
* `score`;
* совпавшие условия;
* отсутствующие условия;
* информацию о выполненных обязательных и дополнительных условиях.

Пример результата:

```text
matched: true
score: 100

matched_conditions:
- продуктовый дизайнер
- стажер

missing_conditions:
[]
```

Важно: совпадение выполняется на основе условий, заданных в фильтре. Семантически близкие формулировки не обязательно считаются одинаковыми. Например, `продуктовый дизайнер` и `дизайнер цифровых продуктов` могут потребовать дополнительной логики нормализации или словаря синонимов.

---

### 📊 Оценка релевантности

При совпадении фильтра система рассчитывает `score`.

Также сохраняется информация о том, какие условия:

* совпали;
* не совпали;
* были исключены.

Это позволяет использовать результат сопоставления не только для отправки уведомления, но и для дальнейшего развития системы ранжирования вакансий.

---

### 🔔 Персональные уведомления

Если новая публикация является вакансией и соответствует активному фильтру, JobMate отправляет пользователю личное сообщение через Telegram Bot API.

Уведомление может содержать:

* название канала;
* подходящие фильтры;
* текст вакансии;
* ссылку на исходный пост.

Пример:

```text
Найдена подходящая вакансия.

Канал: вакансии тест

Подходящие фильтры:
• продуктовый дизайнер

Текст вакансии:
продуктовый дизайнер, стажер

Открыть пост:
https://t.me/testvakansyi/12
```

Для отправки используется `user_id` конкретного пользователя. Общий `NOTIFICATION_CHAT_ID` для всех пользователей не используется.

### Telegram Bot API

`python-telegram-bot` отвечает за:

* команды;
* inline-кнопки;
* главное меню;
* управление каналами;
* управление фильтрами;
* настройки;
* подключение Telegram-аккаунта;
* отправку персональных уведомлений.

---

### Telegram User Client

`Telethon` работает от имени Telegram-аккаунта конкретного пользователя.

Он используется для:

* авторизации пользовательского аккаунта;
* получения доступа к каналам;
* чтения новых публикаций;
* мониторинга каналов;
* передачи новых постов в обработчик вакансий.

Для каждого пользователя используется отдельная сессия.

---

### Telegram Client Manager

`telegram_clients.py` управляет пользовательскими Telethon-клиентами.

Он:

* создаёт клиентов;
* переиспользует существующие сессии;
* устанавливает callback для новых публикаций;
* запускает polling;
* предотвращает запуск нескольких polling-задач для одного пользователя;
* управляет остановкой пользовательских клиентов.

После запуска приложения JobMate проверяет сохранённые пользовательские сессии и автоматически запускает мониторинг для авторизованных пользователей.

---

### MongoDB

MongoDB используется для хранения:

* пользователей;
* Telegram-каналов;
* фильтров;
* обработанных постов;
* состояния мониторинга.

Основные сущности связаны с `user_id`.

Посты также сохраняются с привязкой к:

```text
user_id
channel_id
message_id
```

Это позволяет независимо обрабатывать один и тот же канал для разных пользователей.

## 📦 Установка и запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/Polina-Solovyova/JobMate.git
cd JobMate
```

### 2. Создание виртуального окружения

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Windows:

```bash
python -m venv .venv
.venv\Scripts\activate
```

### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 4. Настройка `.env`

Создайте файл `.env` в корне проекта.

```env
BOT_TOKEN=ваш_токен_бота

MONGO_URI=mongodb+srv://user:password@cluster.mongodb.net/

TELEGRAM_API_ID=ваш_api_id
TELEGRAM_API_HASH=ваш_api_hash

TELEGRAM_SESSION_NAME=jobmate

MONGO_DB_NAME=jobmate
```

### Переменные окружения

| Переменная              | Назначение                  |
| ----------------------- | --------------------------- |
| `BOT_TOKEN`             | токен Telegram-бота         |
| `MONGO_URI`             | строка подключения MongoDB  |
| `TELEGRAM_API_ID`       | Telegram API ID             |
| `TELEGRAM_API_HASH`     | Telegram API Hash           |
| `TELEGRAM_SESSION_NAME` | базовое имя Telethon-сессии |
| `MONGO_DB_NAME`         | название базы MongoDB       |

Следующие переменные в текущей архитектуре не используются:

```text
OWNER_USER_ID
NOTIFICATION_CHAT_ID
```

### 5. Запуск

```bash
python main.py
```

После запуска бот начинает принимать команды, а для уже авторизованных пользователей может автоматически запускать мониторинг каналов.

## 🔑 Получение Telegram API ID и API Hash

Для работы Telethon необходимы:

```text
TELEGRAM_API_ID
TELEGRAM_API_HASH
```

Их можно получить через официальный Telegram-портал разработки:

1. Откройте `my.telegram.org`.
2. Авторизуйтесь под своим Telegram-аккаунтом.
3. Откройте **API development tools**.
4. Создайте приложение.
5. Скопируйте `api_id` и `api_hash`.
6. Добавьте значения в `.env`.

## 🔐 Подключение Telegram-аккаунта

После запуска используйте:

```text
/connect
```

JobMate запускает процесс подключения пользовательского Telegram-аккаунта.

После успешной авторизации создаётся Telethon session-файл.

Сессия используется для доступа к каналам без необходимости авторизовываться при каждом запуске приложения.

При перезапуске JobMate автоматически проверяет сохранённые сессии и запускает мониторинг для авторизованных пользователей.

### Важное ограничение

Telethon session-файл предоставляет авторизованный доступ к Telegram-аккаунту пользователя.

Поэтому session-файлы являются чувствительными данными.

Их нельзя:

* публиковать;
* добавлять в Git;
* отправлять в публичные Issue;
* передавать другим пользователям.

## 🧠 Обработка вакансий

После появления нового поста JobMate выполняет последовательность обработки.

### 1. Получение нового поста

Telethon периодически проверяет отслеживаемые каналы.

Для пользователя используется собственный Telethon-клиент.

При обнаружении нового сообщения формируется объект поста, содержащий, среди прочего:

```text
user_id
channel_id
message_id
text
channel_title
channel_username
```

Пост передаётся в `post_processor()`.

---

### 2. Защита от повторной обработки

Каждый обработанный пост сохраняется в MongoDB.

Идентификация выполняется по:

```text
user_id
channel_id
message_id
```

Это позволяет избежать повторной обработки одного и того же поста для одного пользователя.

При этом один и тот же Telegram-канал может независимо отслеживаться несколькими пользователями.

---

### 3. Определение вакансии

`vacancies.py` анализирует текст публикации.

Используются различные текстовые признаки, позволяющие определить наличие вакансии или предложения о работе.

Результат содержит:

```text
is_vacancy
vacancy_data
matched_filters
```

---

### 4. Получение активных фильтров

Для конкретного пользователя JobMate получает только включённые фильтры:

```python
get_user_filters(
    user_id=user_id,
    enabled_only=True,
)
```

Таким образом фильтры одного пользователя не используются при обработке публикаций другого пользователя.

---

### 5. Сопоставление с фильтрами

`process_post_with_filters()` проверяет публикацию относительно пользовательских фильтров.

Если условия фильтра выполнены, результат может содержать:

```text
filter_id
filter_name
matched
score
matched_conditions
missing_conditions
```

Например:

```text
filter_name: продуктовый дизайнер
matched: true
score: 100

matched_conditions:
- продуктовый дизайнер
- стажер
```

---

### 6. Отправка уведомления

Если:

```text
is_vacancy = true
```

и найден хотя бы один подходящий активный фильтр, JobMate вызывает систему уведомлений.

Пользователю отправляется сообщение через Telegram Bot API.

В `send_vacancy_notification()` используется:

```text
chat_id = user_id
```

Поэтому бот может самостоятельно отправить сообщение пользователю в момент обнаружения подходящей вакансии — пользователю не нужно отправлять команду непосредственно перед уведомлением.

При этом пользователь должен предварительно открыть чат с ботом и запустить его, например через `/start`.

---

## 🔔 Система уведомлений

Уведомления реализованы в `notifications.py`.

Основная логика:

```text
Новый пост
    ↓
Определение вакансии
    ↓
Получение активных фильтров пользователя
    ↓
Сопоставление
    ↓
Есть совпадение?
    ├── Нет → обработка завершается
    │
    └── Да
         ↓
    send_vacancy_notification()
         ↓
    Telegram Bot API
         ↓
    Личное сообщение пользователю
```

Общий чат для уведомлений не используется.

Каждый пользователь получает только те вакансии, которые соответствуют его собственным активным фильтрам.

`main.py` — запуск приложения, обработка событий и регистрация Telegram handlers.

`handlers/channels.py` — пользовательский интерфейс управления каналами.

`handlers/filters.py` — пользовательский интерфейс управления фильтрами.

`handlers/settings.py` — пользовательский интерфейс раздела настроек.

## 🧪 Тестирование

Для ручного тестирования рекомендуется использовать собственный Telegram-канал.

### Проверка авторизации

1. Запустите бота.
2. Выполните `/connect`.
3. Пройдите авторизацию Telegram.
4. Убедитесь, что авторизация завершилась успешно.
5. Перезапустите приложение.
6. Убедитесь, что сохранённая сессия обнаруживается и мониторинг запускается без повторной авторизации.

---

### Проверка каналов

1. Откройте «Мои каналы».
2. Добавьте тестовый канал.
3. Убедитесь, что канал появился в списке.
4. Проверьте включение мониторинга.
5. Проверьте отключение мониторинга.
6. Включите мониторинг снова.
7. Проверьте удаление канала.
8. Проверьте кнопку «Назад».

---

### Проверка фильтров

1. Создайте фильтр.
2. Укажите условия фильтра.
3. Проверьте отображение фильтра.
4. Проверьте редактирование.
5. Проверьте включение и отключение.
6. Проверьте удаление.
7. Проверьте кнопку «Назад».

---

### Проверка уведомлений

Создайте фильтр, например:

```text
продуктовый дизайнер, стажер
```

Затем опубликуйте в тестовом канале новый пост:

```text
продуктовый дизайнер, стажер
```

В логах должны появиться сообщения примерно такого вида:

```text
PROCESSING NEW POST
POST PROCESSOR CALLED
FILTER RESULT
SENDING VACANCY NOTIFICATION
VACANCY NOTIFICATION SENT
```

После этого пользователь должен получить личное сообщение от бота.

Также рекомендуется проверить:

* вакансию, соответствующую фильтру;
* вакансию, не соответствующую фильтру;
* пост, не являющийся вакансией;
* вакансию с отсутствующим обязательным условием;
* вакансию с исключающим условием;
* повторную обработку одного поста.

> Для проверки мониторинга следует публиковать новое сообщение после добавления канала и включения мониторинга.

## 🐛 Возможные проблемы

| Проблема                                                      | Возможное решение                                                                         |
| ------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `BOT_TOKEN is not configured`                                 | Проверьте `BOT_TOKEN` в `.env`.                                                           |
| `MONGO_URI is not configured`                                 | Проверьте строку подключения MongoDB.                                                     |
| Telethon не авторизуется                                      | Проверьте `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`.                                        |
| Сессия Telethon перестала работать                            | Удалите соответствующую сессию и выполните `/connect` повторно.                           |
| Бот не видит канал                                            | Убедитесь, что подключённый Telegram-аккаунт имеет доступ к каналу.                       |
| Канал не обрабатывает новые посты                             | Проверьте, что мониторинг канала включён и пользовательская Telethon-сессия авторизована. |
| В логах есть `PROCESSING NEW POST`, но нет уведомления        | Проверьте `FILTER RESULT` — возможно, ни один активный фильтр не совпал.                  |
| `matched_filters=[]`                                          | Проверьте условия и формат пользовательского фильтра.                                     |
| `is_vacancy=False`                                            | Пост не был распознан как вакансия. Проверьте логи и логику `vacancies.py`.               |
| Нет `SENDING VACANCY NOTIFICATION`                            | Ни один фильтр не был успешно сопоставлен.                                                |
| Есть `SENDING VACANCY NOTIFICATION`, но сообщение не приходит | Проверьте ошибки Telegram Bot API в логах.                                                |
| После перезапуска мониторинг не работает                      | Проверьте наличие и сохранность Telethon session-файла.                                   |
| MongoDB не создаёт индексы                                    | Проверьте доступ приложения к базе данных и права пользователя MongoDB.                   |

### Как читать логи мониторинга

Получение:

```text
Got difference for channel ...
```

означает, что Telethon получил обновление Telegram.

Получение:

```text
PROCESSING NEW POST
```

означает, что новое сообщение уже дошло до обработчика JobMate.

Получение:

```text
FILTER RESULT
```

означает, что публикация была проверена относительно фильтров.

Получение:

```text
SENDING VACANCY NOTIFICATION
```

означает, что найден подходящий фильтр и система приступила к отправке уведомления.

Запросы:

```text
POST .../getUpdates
```

относятся к Telegram Bot API и получению обновлений от бота. Они не являются признаком того, что Telethon получил новую публикацию из отслеживаемого канала.

## 🧩 Расширение функциональности

### Новые правила сопоставления

Основная логика сопоставления находится в:

```text
matching.py
```

Здесь можно расширять:

* нормализацию текста;
* обработку вариантов написания;
* словари синонимов;
* правила сопоставления должностей;
* правила сопоставления навыков;
* fuzzy matching.

При добавлении новых правил необходимо учитывать риск ложных совпадений.

Например:

```text
продуктовый дизайнер
```

и:

```text
дизайнер цифровых продуктов
```

могут обозначать близкие позиции, но не должны автоматически считаться идентичными без соответствующего правила.

---

### Новые признаки вакансий

Логика определения вакансии находится в:

```text
vacancies.py
```

Её можно расширять за счёт:

* ключевых слов;
* признаков найма;
* признаков трудоустройства;
* шаблонов зарплаты;
* должностей;
* навыков;
* стоп-слов;
* других текстовых признаков.

---

### Интервал мониторинга

Polling запускается с заданным интервалом:

```python
await client.start_polling(interval=30)
```

Значение `30` означает, что проверка новых сообщений выполняется примерно каждые 30 секунд.

Интервал можно изменить в коде в зависимости от требований к скорости обнаружения новых публикаций и нагрузки на систему.

## 🔒 Безопасность

JobMate работает с пользовательскими Telegram-сессиями. Это требует особого внимания к безопасности.

### Не храните чувствительные данные авторизации

Не следует сохранять в MongoDB:

* номер телефона;
* код подтверждения Telegram;
* пароль двухфакторной аутентификации.

Эти данные используются только во время процесса авторизации.

---

### Защищайте session-файлы

Telethon session-файл предоставляет авторизованный доступ к Telegram-аккаунту.

Поэтому:

* не публикуйте session-файлы;
* не добавляйте их в Git;
* не отправляйте их в публичные Issue;
* ограничьте доступ к каталогу `sessions/`.

В `.gitignore` должны находиться:

```gitignore
.env

sessions/

*.session
*.session-journal

__pycache__/
*.pyc
```

---

### Токен Telegram-бота

`BOT_TOKEN` также является секретным значением.

Его нельзя:

* публиковать в Git;
* размещать в README;
* отправлять в публичные Issue;
* включать в сообщения об ошибках.

Для хранения токена используется `.env`.

---

### Изоляция пользователей

Запросы к пользовательским каналам и фильтрам выполняются с учётом:

```text
user_id
```

Посты также имеют пользовательскую область:

```text
user_id + channel_id + message_id
```

Это позволяет нескольким пользователям одновременно отслеживать один и тот же Telegram-канал независимо друг от друга.
