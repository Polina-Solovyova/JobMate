# 🚀 JobMate — персональный Telegram-ассистент для поиска вакансий

[![Python Version](https://img.shields.io/badge/python-3.11%2B-blue)](https://www.python.org/)
[![License: AGPL v3](https://img.shields.io/badge/License-AGPL_v3-blue)](https://www.gnu.org/licenses/agpl-3.0)
[![Telegram Bot API](https://img.shields.io/badge/Telegram%20Bot%20API-brightgreen)](https://core.telegram.org/bots/api)
[![Telethon](https://img.shields.io/badge/Telethon-1.x-blueviolet)](https://docs.telethon.dev/)

**JobMate** — персональный Telegram-ассистент для автоматического поиска вакансий в Telegram-каналах.

Пользователь подключает свой Telegram-аккаунт, добавляет доступные ему каналы и задаёт предпочтения по вакансиям. JobMate отслеживает новые публикации, определяет вакансии, извлекает основные характеристики и сопоставляет их с пользовательскими условиями.

Главная идея проекта — постепенно перейти от обычного поиска по ключевым словам к **интеллектуальной рекомендательной системе**, которая сможет учитывать смысл вакансии, профиль пользователя и его поведение.

Каждый пользователь работает со своей Telegram-сессией, каналами, фильтрами и историей обработанных постов. Пользовательские данные изолированы друг от друга.

## 🌟 Возможности

### 👥 Многопользовательский режим

JobMate рассчитан на работу с несколькими пользователями.

Для каждого пользователя отдельно хранятся:

* Telegram-сессия;
* список отслеживаемых каналов;
* фильтры;
* обработанные посты;
* состояние мониторинга.

Основным идентификатором пользовательских данных является `user_id`.

Это позволяет нескольким пользователям независимо отслеживать одни и те же Telegram-каналы.

---

### 🔐 Подключение личного Telegram-аккаунта

Для чтения публикаций JobMate использует Telegram-аккаунт самого пользователя через **Telethon**.

Подключение выполняется через:

```text
/connect
```

После успешной авторизации создаётся отдельная Telethon session-файл пользователя.

При последующих запусках JobMate может использовать существующую авторизованную сессию и автоматически запускать мониторинг для пользователей с доступными сессиями.

> Telethon session-файлы предоставляют авторизованный доступ к Telegram-аккаунту и должны храниться в защищённом месте.

---

### 📢 Мониторинг Telegram-каналов

Пользователь может добавлять Telegram-каналы, доступные его подключённому аккаунту.

В разделе «Мои каналы» доступны операции:

* добавление канала;
* просмотр каналов;
* включение мониторинга;
* отключение мониторинга;
* удаление канала;
* повторная проверка доступа;
* возврат в главное меню.

Для добавления можно использовать username или ссылку:

```text
@vacancies_channel
```

или:

```text
https://t.me/vacancies_channel
```

Канал должен быть доступен подключённому Telegram-аккаунту пользователя.

Для каждого пользователя используется отдельный Telethon-клиент.

---

### 🎯 Персональные фильтры

Пользователь может создавать собственные фильтры для поиска вакансий.

Например:

```text
продуктовый дизайнер, стажер
```

или:

```text
UX/UI дизайнер удалённо без опыта
```

Фильтры поддерживают несколько условий и могут быть:

* созданы;
* просмотрены;
* отредактированы;
* включены;
* отключены;
* удалены.

В текущей версии фильтры используются как основа rule-based matching.

---

### 🧠 Определение и структурирование вакансий

JobMate анализирует текст новых публикаций и определяет, является ли публикация вакансией.

Для найденной вакансии извлекаются основные поля:

```text
title
company
salary
location
experience
description
contacts
skills
raw_text
```

Пример структурированных данных:

```text
title: UI/UX Дизайнер в Softnetix
salary: до 1 500 USD
location: Минск
experience: junior+
skills:
- figma
- ux
- ui
```

Извлечение выполняется на основе текстовых признаков и регулярных выражений.

---

### 🗂 Обработка подборок вакансий

Для публикаций, содержащих несколько вакансий, используется отдельный модуль:

```text
digest_parser.py
```

Он предназначен для выделения отдельных элементов подборки и определения контекста категории.

Поддерживаются категории:

```text
Стажёр
Junior
Middle
Senior
Lead
```

Также предусмотрено определение категории непосредственно из названия вакансии.

Например:

```text
Продуктовый дизайнер (Стажёр)
```

может быть представлен как:

```text
title: Продуктовый дизайнер (Стажёр)
category: Стажёр
```

Парсер старается сохранять исходный текст вакансии, чтобы не терять информацию, необходимую для дальнейшего matching.

---

### 🔎 Rule-based matching

В текущей версии сопоставление выполняется модулем:

```text
matching.py
```

Используются:

* нормализация текста;
* морфологическая обработка;
* словари и синонимы;
* fuzzy matching;
* обязательные условия;
* дополнительные условия;
* исключающие условия;
* итоговый score.

Результат содержит:

```text
filter_id
filter_name
matched
score
matched_conditions
missing_conditions
```

Например:

```text
filter_name: продуктовый дизайнер
matched: true
score: 100

matched_conditions:
- продуктовый дизайнер
- стажер

missing_conditions:
[]
```

Текущий matching остаётся преимущественно правиловым. Это сознательная базовая версия перед переходом к семантическому и персонализированному ранжированию.

---

### 🔔 Персональные уведомления

Если найденная вакансия соответствует пользовательским условиям, JobMate отправляет персональное сообщение через Telegram Bot API.

Уведомление может содержать:

* название канала;
* подходящие фильтры;
* текст вакансии;
* ссылку на исходный пост.

Если одна вакансия соответствует нескольким фильтрам, подходящие фильтры объединяются в одном уведомлении.

Пример:

```text
Найдена подходящая вакансия.

Канал: вакансии тест

Подходящие фильтры:
• продуктовый дизайнер
• UX/UI дизайнер

Текст вакансии:

UI/UX Designer в Softnetix
...

Открыть пост:
https://t.me/testvakansyi/12
```

Уведомление отправляется непосредственно пользователю:

```text
chat_id = user_id
```

Общий `NOTIFICATION_CHAT_ID` не используется.

## Telegram Bot API

`python-telegram-bot` отвечает за взаимодействие с пользователем:

* `/start`;
* `/connect`;
* главное меню;
* inline-кнопки;
* управление каналами;
* управление фильтрами;
* настройки;
* отправку уведомлений.

---

## Telegram User Client

`Telethon` работает от имени подключённого Telegram-аккаунта пользователя.

Используется для:

* авторизации;
* доступа к каналам;
* получения новых публикаций;
* мониторинга каналов;
* передачи новых постов в обработчик.

Для каждого пользователя используется собственная сессия.

---

## Telegram Client Manager

`telegram_clients.py` управляет пользовательскими Telethon-клиентами.

Он отвечает за:

* создание клиентов;
* переиспользование существующих клиентов;
* восстановление сессий;
* запуск polling;
* предотвращение нескольких polling-задач одного пользователя;
* остановку клиентов.

После запуска приложения JobMate проверяет пользователей с доступными сессиями и запускает мониторинг.

---

## MongoDB

MongoDB используется для хранения:

* пользователей;
* Telegram-каналов;
* фильтров;
* обработанных постов;
* состояния мониторинга.

Пользовательские данные связаны с:

```text
user_id
```

Обработанные посты идентифицируются с учётом:

```text
user_id
channel_id
message_id
```

Это позволяет независимо обрабатывать один Telegram-канал для разных пользователей.

# 📦 Установка и запуск

## 1. Клонирование репозитория

```bash
git clone https://github.com/Polina-Solovyova/JobMate.git
cd JobMate
```

## 2. Создание виртуального окружения

### Linux/macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### Windows

```bash
python -m venv .venv
.venv\Scripts\activate
```

## 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

## 4. Настройка `.env`

Создайте файл `.env` в корне проекта:

```env
BOT_TOKEN=ваш_токен_бота

MONGO_URI=mongodb+srv://user:password@cluster.mongodb.net/

TELEGRAM_API_ID=ваш_api_id
TELEGRAM_API_HASH=ваш_api_hash

TELEGRAM_SESSION_NAME=jobmate

MONGO_DB_NAME=jobmate
```

### Переменные окружения

| Переменная              | Назначение                  |
| ----------------------- | --------------------------- |
| `BOT_TOKEN`             | токен Telegram-бота         |
| `MONGO_URI`             | строка подключения MongoDB  |
| `TELEGRAM_API_ID`       | Telegram API ID             |
| `TELEGRAM_API_HASH`     | Telegram API Hash           |
| `TELEGRAM_SESSION_NAME` | базовое имя Telethon-сессии |
| `MONGO_DB_NAME`         | название базы MongoDB       |

## 5. Запуск

```bash
python main.py
```

После запуска бот начинает принимать команды.

Для пользователей с сохранёнными авторизованными Telegram-сессиями мониторинг может запускаться автоматически.

# 🧠 Обработка вакансий

После появления нового сообщения JobMate проходит несколько этапов.

## 1. Получение нового поста

Telethon получает новую публикацию из отслеживаемого канала.

В обработчик передаются данные, среди которых:

```text
user_id
channel_id
message_id
text
channel_title
channel_username
```

---

## 2. Защита от повторной обработки

Обработанные сообщения сохраняются в MongoDB.

Для идентификации используется:

```text
user_id
channel_id
message_id
```

Это позволяет избежать повторной обработки одного и того же сообщения для одного пользователя.

---

## 3. Определение вакансии

Модуль:

```text
vacancies.py
```

анализирует публикацию.

Используются:

* индикаторы вакансий;
* признаки найма;
* признаки занятости;
* зарплатные шаблоны;
* контактные данные;
* текстовые признаки.

Если публикация не похожа на вакансию, она не передаётся дальше как обычная вакансия.

---

## 4. Извлечение данных

Для вакансии извлекаются:

```text
title
company
salary
location
experience
description
contacts
skills
raw_text
```

Например:

```text
title:
UI/UX Дизайнер в Softnetix

salary:
до 1 500 USD

location:
Минск

experience:
junior+

skills:
figma
ux
ui
```

---

## 5. Обработка подборок

Для сложных публикаций с несколькими вакансиями используется:

```text
digest_parser.py
```

Парсер пытается определить отдельные элементы и контекст категории.

Например:

```text
Стажёры

Product Designer
...

Frontend Developer
...

Senior

UX Designer
...
```

может быть представлен как несколько независимых элементов.

---

## 6. Matching

После извлечения вакансии она проверяется относительно пользовательских условий.

Основная функция обработки:

```text
process_post_with_filters()
```

Результат проверки содержит:

```text
matched_filters
filter_results
```

Каждый результат может содержать:

```text
filter_id
filter_name
matched
score
matched_conditions
missing_conditions
```

---

## 7. Уведомление

Если найдено совпадение, JobMate отправляет пользователю персональное уведомление.

Для одной вакансии формируется одно уведомление, в котором могут быть перечислены несколько подходящих фильтров.

# 🤖 Развитие рекомендательной системы

Текущий rule-based matching является базовой версией системы.

Основная проблема такого подхода — зависимость от конкретных формулировок.

Например:

```text
продуктовый дизайнер
```

и:

```text
дизайнер цифровых продуктов
```

могут описывать очень похожие позиции, но обычный keyword/fuzzy matching не всегда способен корректно определить их смысловую близость.

Поэтому дальнейшее развитие JobMate планируется как переход от **фильтрации** к **персональному ранжированию вакансий**.

## Этап 1 — Semantic Matching

Добавить embeddings для представления:

* вакансий;
* пользовательских предпочтений;
* должностей;
* навыков.

После этого система сможет оценивать смысловую близость, а не только совпадение слов.

```text
Профиль пользователя
        ↓
     Embedding
        ↓
        ↕
Semantic Similarity
        ↕
     Embedding
        ↑
      Вакансия
```

---

## Этап 2 — Hybrid Matching

Объединить semantic matching с точными ограничениями.

Например:

```text
Hard constraints
├── локация
├── формат работы
├── исключённые позиции
└── критичные требования

Semantic score
├── соответствие должности
├── соответствие навыков
├── сходство описания
└── сходство предпочтений
```

Это позволит не отбрасывать вакансию только из-за другой формулировки, но при этом сохранять важные ограничения пользователя.

---

## Этап 3 — Ranking

Вместо:

```text
подходит / не подходит
```

система будет формировать рейтинг:

```text
1. UI/UX Designer          94%
2. Product Designer        91%
3. Web Designer             83%
4. Graphic Designer         67%
5. 3D Designer              32%
```

Пользователь будет получать наиболее релевантные вакансии в первую очередь.

---

## Этап 4 — Обратная связь пользователя

В интерфейс можно добавить действия:

```text
👍 Подходит

👎 Не подходит

🔖 Сохранить

📨 Откликнуться
```

Эти действия станут данными для персонализации.

Например:

```text
Вакансия A → 👍
Вакансия B → 👍
Вакансия C → 👎
Вакансия D → 👍
```

---

## Этап 5 — Персональная ML-модель

После накопления достаточного количества пользовательских взаимодействий можно обучать модель, которая оценивает:

```text
P(user likes vacancy)
```

И использовать её для персонального ранжирования.

Итоговая архитектура:

```text
                 USER PROFILE
                      │
                      ▼
                User Embedding
                      │
                      │
                      ▼
                 ┌───────────┐
                 │  Ranking  │
                 │   Model   │
                 └─────┬─────┘
                       ▲
                       │
                 Job Embedding
                       ▲
                       │
                    VACANCY

              + Hard Constraints
              + User Feedback
              + Interaction History
```

Таким образом JobMate постепенно переходит от системы поиска по фильтрам к **персональной рекомендательной системе вакансий**.

## Проверка matching

Рекомендуется проверить:

* частичное совпадение;
* fuzzy matching;

* несколько совпавших фильтров;
* вакансию, которая не соответствует фильтрам.

---

## Проверка уведомлений

При совпадении в логах должны появляться сообщения, связанные с:

```text
PROCESSING NEW POST
POST TYPE
FOUND ... vacancy item(s)
MATCH
POST PROCESSING COMPLETE
```

Пользователь должен получить персональное сообщение от бота.

Также необходимо проверить ситуацию, когда одна вакансия подходит нескольким фильтрам.

В этом случае должно отправляться **одно уведомление**, содержащее все подходящие фильтры.

# 🐛 Возможные проблемы

| Проблема                                 | Возможное решение                                                  |
| ---------------------------------------- | ------------------------------------------------------------------ |
| `BOT_TOKEN is not configured`            | Проверьте `BOT_TOKEN` в `.env`                                     |
| `MONGO_URI is not configured`            | Проверьте строку подключения MongoDB                               |
| Telethon не авторизуется                 | Проверьте `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`                  |
| Сессия Telethon перестала работать       | Удалите соответствующую сессию и выполните `/connect` повторно     |
| Бот не видит канал                       | Проверьте доступ подключённого Telegram-аккаунта к каналу          |
| Канал не обрабатывает новые посты        | Проверьте, включён ли мониторинг и авторизована ли Telethon-сессия |
| Пост обнаруживается, но уведомления нет  | Проверьте результаты matching в логах                              |
| `matched_filters=[]`                     | Проверьте пользовательские фильтры и результаты сопоставления      |
| Вакансия не определяется                 | Проверьте текст поста и признаки в `vacancies.py`                  |
| Неправильно определяется title           | Проверьте `_extract_title()` в `vacancies.py`                      |
| Дайджест не разбивается                  | Проверьте `digest_parser.py`                                       |
| После перезапуска мониторинг не работает | Проверьте сохранность Telethon session-файла                       |
| MongoDB недоступна                       | Проверьте `MONGO_URI`, сетевой доступ и права пользователя         |

---

## Как читать логи

### `PROCESSING NEW POST`

Новый пост получен от Telethon и передан в JobMate.

### `POST TYPE`

Определён тип публикации.

### `FOUND ... vacancy item(s)`

JobMate выделил указанное количество вакансий.

### `VACANCY #...`

Информация об отдельной обработанной вакансии.

### `MATCH`

Для вакансии найдено совпадение с пользовательскими условиями.

### `POST PROCESSING COMPLETE`

Обработка поста завершена.

Запросы:

```text
POST .../getUpdates
```

относятся к Telegram Bot API и получению обновлений от бота. Они не означают получение новой публикации из отслеживаемого канала.

# 🔒 Безопасность

JobMate работает с пользовательскими Telegram-сессиями, поэтому необходимо защищать данные авторизации.

## Session-файлы

Telethon session-файлы нельзя:

* публиковать;
* добавлять в Git;
* отправлять в публичные Issue;
* передавать другим пользователям.

В `.gitignore` должны находиться:

```gitignore
.env

sessions/

*.session
*.session-journal

__pycache__/
*.pyc
```

---

## Переменные окружения

Секретные значения должны храниться в `.env`.

Нельзя публиковать:

```text
BOT_TOKEN
TELEGRAM_API_HASH
MONGO_URI
```

в GitHub, README или публичных сообщениях.

---

## Telegram-авторизация

Не следует сохранять в MongoDB:

* номер телефона;
* код подтверждения;
* пароль двухфакторной аутентификации.

Эти данные используются только во время авторизации.

---

## Изоляция пользователей

Все пользовательские операции должны выполняться с учётом:

```text
user_id
```

Обработанные посты идентифицируются через:

```text
user_id + channel_id + message_id
```

Это позволяет пользователям независимо отслеживать один и тот же Telegram-канал.
